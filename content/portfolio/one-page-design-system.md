**Working idea.** A small design system can make an experiment easier to change without creating a library before one is needed.

The first system does not need to predict every screen. It can capture the decisions that help a reader recognize the interface and help its maker revise it.

## Write down four decisions

Begin with the choices that appear across the concept:

1. **Surface:** Which areas need a clear background or boundary?
2. **Text:** Which type sizes carry the main message and supporting detail?
3. **Action:** How does a primary action look beside a secondary one?
4. **Spacing:** What repeated gaps keep groups easy to scan?

Give each choice a role, such as **page**, **surface**, **text**, **muted**, and **action**. Role names explain intent. Names such as **blue-2** or **small-padding** describe only one current value.

## Make the page useful

A one-page note can show a heading, a paragraph, a button, a field, and a card. Add the chosen values beside each sample. Include one narrow layout if mobile behavior affects the question.

Record the typeface, minimum contrast target, and spacing unit. Then a reviewer can discuss the rule without guessing from a screenshot.

## Add rules when repetition earns them

Do not create a token for every color or component at the start. Add a rule when repeated use exposes a real choice or a cost of inconsistency.

For example, a concept might begin with one action style. If a second action needs a different level of emphasis, record that distinction and explain when to use it.

This approach keeps the first version easy to revise. It also leaves a trail from each rule to the problem it solves.

## Keep the system provisional

A one-page system is a proposal for shared decisions. It can change as the concept changes.

The useful question is not how many components the system contains. Ask whether it helps people make, review, and change the work with less confusion.
